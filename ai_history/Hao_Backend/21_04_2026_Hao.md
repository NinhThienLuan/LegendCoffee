## 1. Mục lục các thành phần đã chỉnh sửa & Khởi tạo (Chi tiết để truy xuất)

Dưới đây là danh sách đầy đủ các File code đã được tác động trong quá trình xây dựng tính năng vận chuyển:

### A. Tầng Giao diện & Điều hướng (Controller)
1.  **`OrderController.java`**: 
    *   Đã thêm route `/orders/{orderId}/track` để hiển thị trang theo dõi.
    *   Đã sửa đổi route `/orders/{orderId}/cancel` (Fix redirect về `/track`).
2.  **`ShippingController.java` (New)**: 
    *   Cung cấp các API AJAX cho Frontend: `/provinces`, `/districts`, `/wards`.
    *   API tính phí vận chuyển real-time: `/options`.
3.  **`GHNWebhookController.java` (New)**: 
    *   Xử lý Webhook từ GHN tại `/webhook/ghn`. Cập nhật trạng thái tự động mà không cần can thiệp thủ công.

### B. Tầng Nghiệp vụ (Service)
1.  **`GHNService.java` & `GHNServiceImpl.java`**: 
    *   Định nghĩa toàn bộ các Header, cấu trúc bảo mật HMAC-512.
    *   Triển khai gọi các API GHN: Tạo đơn, Huỷ đơn, Lấy chi tiết đơn, Tính phí, Tính ngày giao, Master Data.
2.  **`ShippingService.java` & `ShippingServiceImpl.java`**: 
    *   Xử lý logic `createGHNOrder`: Kết hợp lưu `Order` và gọi GHN.
    *   **Logic Huỷ đơn (`cancelShipping`):** Đã bổ sung check trạng thái DB nội bộ trước khi gọi API GHN.
    *   Logic dựng Timeline: Map các trạng thái từ GHN sang nhãn tiếng Việt hiển thị trên giao diện.

### C. Tầng Dữ liệu (Entity & Repository)
1.  **`ShippingInfo.java` (Entity)**: 
    *   Khởi tạo bảng lưu trữ: `ghn_order_code`, `status`, `recipient_name`, `recipient_phone`, `shipping_fee`, `expected_delivery_time`,...
2.  **`ShippingInfoRepository.java`**: 
    *   Thêm các phương thức truy vấn: `findByOrderId`, `findByGhnOrderCode`.
    *   Thêm `@Modifying` query `updateStatusByGhnOrderCode` phục vụ cho Webhook.

### D. Giao diện (Thymeleaf Templates)
1.  **`order-tracking.html` (New)**: 
    *   Layout hiển thị bản đồ hành trình đơn hàng.
    *   Sử dụng Timeline dọc để liệt kê trạng thái.
    *   Nút "Huỷ đơn hàng" có tích hợp logic ẩn/hiện (`th:if`) và xác nhận JS.

## 2. Chi tiết Luồng Vận Chuyển Toàn Diện (End-to-End Workflow)

1.  **Chọn địa chỉ động (AJAX):** Khách hàng chọn địa chỉ -> `ShippingController` gọi GHN Master Data -> Trả về danh sách cấp 2, 3.
2.  **Khởi tạo đơn:** `OrderController` -> `ShippingService.createGHNOrder` -> Gọi GHN API `/create` -> Lưu `ShippingInfo` và gắn kết với `Order`.
3.  **Webhook Updates:** Server GHN -> `GHNWebhookController` -> `ShippingService.handleWebhook` -> Cập nhật trạng thái mới nhất vào Database.
4.  **Huỷ đơn an toàn:** Kiểm tra "nguồn chân lý" tại Database. Nếu status là `ready_to_pick`, tiến hành gọi lệnh huỷ sang GHN và cập nhật lại DB nội bộ.

## 3. Nhật ký Code Fix & Tối ưu hoá (Hôm nay)

*   **Tại `ShippingServiceImpl.java`:** 
    - Bổ sung logic tiền kiểm tra DB trước khi huỷ.
    - **Request:** `orderId`. **Logic:** Kiểm tra `ShippingInfo` if `!ready_to_pick` -> `return false`.
    - **Lý do:** Tăng tốc độ huỷ, tránh gọi API không cần thiết khi hàng đã thực sự rời kho.

*   **Tại `OrderController.java`:**
    - Fix redirect: `return "redirect:/orders/" + orderId + "/track";`.
    - **Kết quả:** Người dùng luôn ở lại trang theo dõi để nhận feedback chính xác về lệnh huỷ đơn.

## 4. Tham khảo Mapping thông tin (Glossary)

- **ready_to_pick**: Đơn mới tạo, đang chờ shipper đến lấy. (Được huỷ).
- **picking**: Shipper đang đi lấy hàng. (Hạn chế huỷ).
- **transporting / delivering**: Hàng đang di chuyển hoặc đang đi giao. (Không được huỷ).
- **delivered**: Đã giao thành công.
- **cancel**: Đơn đã bị huỷ.
